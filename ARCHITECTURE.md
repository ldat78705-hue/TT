Key Architecture Patterns\n\n### Firestore Sharding\n- **NON_SHARDED** (single doc each): students, teachers, staff, classes, progressReports, announcements, settings, auditLogs, rooms\n- **SHARDED** (by month): attendance → `attendance_YYYY_MM_classId`, invoices → `invoices_YYYY_MM`, transactions → `transactions_YYYY_MM`, income → `income_YYYY_MM`, expenses → `expenses_YYYY_MM`, payrolls → `payrolls_YYYY_MM`\n- Purpose: Overcome Firestore 1MB document size limit\n\n### 3-Layer Caching\n1. **Server in-memory**: Per-center cache with raw string comparison for dirty-checking\n2. **HTTP ETag/304**: syncId as ETag, client sends If-None-Match\n3. **Client sessionStorage**: Stores ETag for conditional requests\n\n### Optimistic Updates\n- `DataContext.handleStateUpdateOperation()` applies operation locally first via `applyOperation()` (same pure function used server-side)\n- Server response replaces local state on success\n- Rollback on error\n\n### Multi-Tenant\n- `centers_registry` Firestore collection stores center metadata\n- Each center: `center_{slug}` Firestore collection\n- Center lifecycle: create (30-day trial) → extend → lock/unlock → delete\n- Center status validated on every API request (1-min TTL cache)\n- Default super admin: `superadmin` / `Thanhdat`\n\n### Auth Flow\n- JWT HS256 via jose library, 30-day expiry\n- Password: bcrypt (10 rounds), backward-compatible with SHA-256 and plaintext\n- Session: localStorage `educenter_user_session` (userId, role, token)\n- Forced password change for default/DOB passwords\n- Cross-center auth: tries all active centers if no centerId\n\n### Role-Based Access Control\n| Role | Data Access | Write Operations |\n|------|------------|------------------|\n| ADMIN | Full | All |\n| MANAGER | Full | All except settings, clearCollections |\n| ACCOUNTANT | Full | Financial operations only |\n| TEACHER | Own classes/students only, balance hidden | Attendance, progress, announcements (own only) |\n| PARENT | Own student only | Password change, leave request (EXCUSED_ABSENT) |\n| VIEWER | Full (read-only) | None |\n\n---\n\n## 6. Key Implementation Details\n\n### Invoice Generation (`generateInvoices`)\n- Calculates fees per student per class based on fee type:\n  - **MONTHLY**: Fixed monthly amount (with discount)\n  - **PER_SESSION**: Count attended sessions × rate (with discount)\n  - **PER_COURSE**: One-time course fee (tracked via `billedCourses[]`)\n- Pre-calculates attendance data to avoid O(N³)\n- Creates/updates invoices and related INVOICE transactions\n- Recalculates student balances\n\n### Balance Recalculation (`recalculateStudentInvoices`)\n3-pass algorithm:\n1. Deduct PAID invoices from available funds\n2. Revoke PAID status from newest invoices if funds insufficient\n3. Distribute remaining funds to UNPAID invoices oldest-first\n4. 100VND tolerance buffer\n\n### Attendance Transaction\n- Uses Firestore `runTransaction()` for atomic writes\n- Groups records by shard key, reads only affected shard documents\n- Updates in-place in cache after commit (avoids full re-read)\n\n### Parent Leave Request\n- `updateSingleAttendance` with EXCUSED_ABSENT status\n- Auto-creates teacher notification announcement\n- Parents can only submit for their own student\n\n### Webhook Payment Processing\n1. Parse payload (raw SMS or structured JSON)\n2. Detect debit (skip outgoing)\n3. Extract amount (priority regex chain)\n4. Extract student ID (configurable prefix)\n5. Duplicate detection (2-layer)\n6. Amount cap check\n7. Execute addAdjustment CREDIT\n8. Create announcement + Zalo confirmation\n\n---\n\n## 10.
